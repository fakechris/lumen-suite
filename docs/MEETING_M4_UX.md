# 会议模式 M4 — UX 设计与实施

状态：v1，2026-07-28。落地 lumen-asr（apps/desktop 前端 + src-tauri 后端 + lumen-prompts）。承接 docs/MEETING.md 的 Stage M4。

## 一句话定义

> 会议库是入口，纪要是结果，逐字稿是证据，播放器是验证工具，说话人修正是现场多人会议的必要纠错机制。

参照谱系：外层"列表 + 详情页"；详情页 = **Granola 纪要优先 + Otter 转录/播放联动 + Descript-lite 说话人修正**。**不做** Descript 多轨时间线、不做卡片瀑布、不默认打开逐字稿、播放器固定底部。产品是"会议记录与理解工具"，不是音频制作软件。

## v1 的三个技术裁决（与离线架构对齐）

1. **录制窗口不显示实时逐字稿 / 实时说话人计数**。diar + 逐段 ASR 都在停止后离线跑（说话人分离需要整段音频），v1 无流式。录制中只显示：正在录 / 时长 / 麦克风电平 / 存储正常 / 「标记此刻」/ 暂停 / 结束。转录与说话人在停止后的详情页出现。（流式实时预览 = 未来增强。）
2. **纪要是结构化输出，不是 Markdown**。为支持"纪要条目点击跳原文/音频"，minutes LLM 产出结构化 JSON，每条决策/行动项带 `source`（segment id / 时间范围）。前端渲染为可点击项。行动项结构化（负责人 / 截止 / 来源范围）。
3. **JSON 导出 = `lumen-transcript.v1`**（= Cut 导入格式）。"会议数据.json"即 Cut 一键导入的格式，导出与"送 Cut 精修"合一。

## 信息架构

### 会议主页面：高密度列表（非卡片）
左侧过滤（全部 / 收藏 / 待处理 / 处理中 / 失败 / 最近标签），右侧按日期分组的列表。每条：标题、日期/开始时间/时长、说话人数、一行纪要摘要、状态（录制中/转录中/总结中/完成/失败）、收藏、必要时警示（音频质量差 / 有未确认说话人）。M4 只做：搜索、日期分组、收藏、状态过滤（复杂文件夹以后）。

### 会议详情：**逐字稿优先 + 纪要作左侧窄索引**（2026-07-29 dogfood 修订，推翻原"默认纪要"）

用户实测反馈：进详情先看到一堆"关键讨论"、要再点一下才看到逐字稿，"点来点去"体验差。改为：**逐字稿默认直接可见**（主区），**纪要/关键讨论/决策/行动项收进左侧一条窄索引栏**，点索引项跳转到逐字稿对应位置（用 source 时间戳滚动定位）。不再需要 tab 切换才能看逐字稿。（原 Granola 式"默认纪要页"作废；纪要内容仍在，只是变成左侧索引 + 可选完整视图。）

#### 原设计（保留作参考）：纪要 / 逐字稿 双视图，默认纪要
顶部统一标题栏（标题、时间·时长·说话人数、`[纪要][逐字稿]`、`[···][导出]`）。
- **纪要页**：一句话总结 / 决策 / 行动项 / 关键讨论 / 未决问题 /（可选议题章节）。**每条带时间戳，点击跳到逐字稿+音频**。右栏参与者 + 会议信息。行动项结构化（负责人、截止、来源 mm:ss–mm:ss）。
- **逐字稿页（阅读器，非编辑器）**：按**说话轮次**分段（连续同一人合并为一段，一段一个时间戳）；当前播放段浅色高亮 + 点击段落跳转；**无词级高亮**（v1）；自动滚动，手动滚动后暂停跟随 + 浮动「继续跟随」；说话人 = 姓名 + 首字母头像 + 淡色 + 左侧小色条（**不**整段变色）。右栏说话人列表（占比、声音样本、重命名/合并/识别）。
- **底部固定播放器**：播放/进度条/±5s/倍速。跳转与高亮联动。

### 说话人修正（现场会议核心）
说话人是**待确认聚类**（Speaker 1/2…），非确定身份，UI 必须如此呈现（未确认的不要显示得像真名）。点击某 speaker → 播放 ~8s 代表样本 → 绑定为（新建 / 已有联系人 / 本场某人）+ 应用范围（**整簇** / **仅当前段**）。四种操作：
1. 重命名整个 cluster（Speaker 3 → 李明）
2. 仅改当前段（模型偶尔把一句话分错人）
3. 合并两个 speaker（实为同一人）
4. 标记未知（不强迫命名）
全局 speaker profile / 跨会议自动识别 → **M5**。M4 只做本场闭环。

### 录制窗口（与会后详情分离，克制）
独立小窗：`● 正在录制 时长`、麦克风名+电平、存储状态、「标记此刻」（生成 `★ 重点时刻 mm:ss`）、暂停、结束。不要求会中命名/编辑/读实时纪要。

### 导出（预设优先）
M4 做四个固定预设：`会议纪要.md`、`完整逐字稿.md`、`字幕.srt`、`会议数据.json`（= lumen-transcript.v1）。选项（含时间戳/说话人/行动项/音频）以后再放开自由组合。

## 子阶段拆分

### M4a：后端管线闭环 + 结构化纪要 + 说话人操作（无 UI，可测）
- 录制 stop → **自动跑 M2b 转录** → 跑结构化 **minutes**（lumen-prompts 新增 minutes intent，产出 JSON：总结/决策/行动项/讨论/未决，每条带 source segment/时间）→ 状态推进 recording→processing→transcribing→summarizing→ready/failed。
- Store 补说话人操作：`rename_speaker`（有）、`reassign_segment_speaker`（单段改人）、`merge_speakers`（B 的段并入 A、删 B）、按 meeting 读 segments+speakers+summary 的查询。
- 导出函数：4 预设（md/md/srt/lumen-transcript.v1 json）。
- Tauri 命令 + 查询供前端调用。单测覆盖：状态机、说话人合并/改段、minutes JSON 解析、导出。diar/ASR 真集成 #[ignore]。
**归属**：lumen-asr（src-tauri、lumen-store、lumen-prompts、lumen-meeting、export）

### M4b：会议库列表 + 详情壳 + 纪要页
"meeting" TabId + 高密度列表（搜索/日期分组/收藏/状态过滤）+ 详情页壳（纪要/逐字稿切换，默认纪要）+ 纪要页（结构化、条目可点跳转）。

### M4c：逐字稿阅读器 + 底部播放器 + 说话人修正 UI
说话轮次分段、当前段高亮、点击跳转、自动滚动+暂停跟随、固定底部播放器；说话人修正交互（样本播放 + 四操作）。

### M4d：录制窗口 + 导出面板
克制录制窗（电平/时长/标记此刻/暂停/结束）+ 四预设导出面板。

## 明确不做（v1）
Descript 多轨时间线、删字剪音频、词级时间轴、大卡片首页、默认逐字稿、顶部随滚消失的播放器、高饱和整段配色、把未确认 Speaker 显示成真身份、无出处的 AI 纪要、跨会议搜索/协作评论/参与度分析/自动邮件任务（均后置）。
